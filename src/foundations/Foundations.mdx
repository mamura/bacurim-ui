# Foundations

Bacurim UI foundations define the shared visual language used across the library.
Colors, typography, spacing, radius, shadows, and breakpoints work together to
create consistent, readable, and responsive interfaces.

Use this overview for usage guidance and open each Story to inspect its visual
examples and token names.

## Token usage principles

- Prefer semantic color tokens that describe a role, such as `primary`, `surface`,
  or `text-primary`, over raw palette values or hard-coded colors.
- Use the shared typography utilities and spacing, radius, and shadow scales.
- Keep equivalent roles consistent across components. A primary action should
  use the same semantic color family wherever it appears.
- Pair action colors with their corresponding contrast tokens, and use the
  dedicated hover and active tokens for interaction states.
- Check contrast, keyboard focus, and readability in context. Token selection
  alone does not guarantee an accessible component.
- Introduce new tokens in the foundation when a reusable need emerges, rather
  than repeating isolated values in components.

The examples below use the utilities provided by the foundation styles and
Tailwind CSS. They assume the application's existing foundation styles are loaded.
Code blocks are usage examples, rather than live component previews.

Primary, secondary, accent, and feedback families also expose `-soft`, `-hover`,
`-active`, and `-contrast` variants. Choose the variant by its intended role.
Do not communicate status through color alone; include a meaningful text label.

```tsx
export function PrimaryAction() {
  return (
    <button
      type="button"
      className="body-sm rounded-sm bg-primary px-4 py-2 text-primary-contrast hover:bg-primary-hover active:bg-primary-active focus-visible:outline-2 focus-visible:outline-offset-2 focus-visible:outline-primary"
    >
      Save changes
    </button>
  );
}
```

Font weight tokens are `--font-weight-regular` (400),
`--font-weight-medium` (500), `--font-weight-semibold` (600), and
`--font-weight-bold` (700).

Choose HTML heading levels according to document structure, independently of
visual size. Use body styles for readable paragraphs and reserve caption text
for brief supporting information.

```tsx
export function SectionIntroduction() {
  return (

      <h2 className="heading-md text-text-primary">Account overview</h2>

        Review your account details and recent activity.
      </p>
    </header>
  );
}
```

utilities multiply that unit: `p-4` applies `1rem` of padding, and `gap-6`

Prefer flex or grid `gap` utilities for sibling spacing, and use padding for
the space inside a container. Avoid arbitrary spacing values when the shared
scale meets the layout's needs.

```tsx
  return (
    <div className="flex flex-col gap-4 p-6">
      <h2 className="heading-sm text-text-primary">Preferences</h2>
      <p className="body-md text-text-secondary">
        Manage the settings that shape your experience.
      </p>
    </div>
  );
}
```

## Breakpoints

Bacurim UI follows a mobile-first approach. Unprefixed utilities define the
base layout for all viewport widths. Responsive prefixes apply at their
minimum width and continue at larger widths unless another utility overrides
the same property.

Pixel equivalents assume the browser's default 16px initial font size.
Choose layout changes based on available space and content needs. A `sm:`
prefix means “at the small breakpoint and above,” rather than “mobile only.”
Resize the Storybook viewport to inspect behavior between thresholds as well
as at the documented widths.

```tsx
export function ResponsiveGrid() {
  return (
    <div className="grid grid-cols-1 gap-4 sm:grid-cols-2 lg:grid-cols-3">
      {['Overview', 'Activity', 'Settings'].map((label) => (
        <div
          key={label}
          className="rounded-md border border-border bg-surface p-6"
        >
          <h2 className="heading-sm text-text-primary">{label}</h2>
        </div>
      ))}
    </div>
  );
}
```

## Putting the foundations together

This example combines semantic colors, typography, spacing, radius, elevation,
and responsive layout in a single component. The action is supplied by its
consumer; the example introduces no application-specific business behavior.

```tsx
type OverviewCardProps = {
  onViewDetails: () => void;
};

export function OverviewCard({ onViewDetails }: OverviewCardProps) {
  return (
    <section
      aria-labelledby="overview-card-title"
      className="flex flex-col gap-6 rounded-md border border-border bg-surface p-4 shadow-sm md:flex-row md:items-center md:justify-between md:p-6"
    >
      <div className="flex flex-col gap-2">
        <span className="caption text-primary">Overview</span>
        <h2 id="overview-card-title" className="heading-md text-text-primary">
          Your workspace at a glance
        </h2>
        <p className="body-md text-text-secondary">
          Keep your information organized and easy to find.
        </p>
      </div>

      <button
        type="button"
        onClick={onViewDetails}
        className="body-sm shrink-0 rounded-sm bg-primary px-4 py-3 text-primary-contrast hover:bg-primary-hover active:bg-primary-active focus-visible:outline-2 focus-visible:outline-offset-2 focus-visible:outline-primary"
      >
        View details
      </button>
    </section>
  );
}
```

When rendering multiple copies, give each heading a unique ID and update its
section's `aria-labelledby` accordingly.
